# Windows 睡眠、休眠与开盖后的自动识别设计

日期：2026-10-03。状态：已实现，并通过本地构建及确定性测试；未进行新的虚拟机或实机电源实验。
实现基于已合并的 PR #104，单独提交恢复识别代码；与此前部署修复、锁屏提示实验分开。

## 目标与产品行为

开启自动识别后，用户从睡眠、休眠或合盖状态回到登录界面时，可以开始一轮
新的识别，即使睡前的识别已经超时。识别通过后继续走现有 Windows 凭据提交链。
恢复事件本身不构成身份验证成功，也不复用睡前尚未提交的识别结果。

沿用现有自动／手动设置、启动延迟、重试间隔和总超时，不增加一组电源专用设置。
自动模式默认包含恢复后重新识别；手动模式恢复后保持待命，仍需 Enter／登录箭头。

| 场景 | 自动模式 | 手动模式 |
| --- | --- | --- |
| 睡眠或休眠后，用户唤醒并返回锁定会话 | 对当前选中的人脸卡片启动一轮新识别 | 恢复待命，等用户触发 |
| 合盖进入睡眠／休眠，再开盖 | 合并恢复、开盖和亮屏通知，只启动一轮 | 同上 |
| 合盖设置为“不执行任何操作”，再开盖 | 会话已锁定且选中人脸卡片时启动一轮 | 同上 |
| 合盖不锁屏，开盖仍是桌面 | 无需解锁，不启动识别 | 不启动 |
| 锁屏后熄屏，再重新亮屏 | 可重启一次已超时的识别 | 保持待命 |
| 定时维护唤醒，屏幕仍关闭 | 等待用户返回，不启动相机 | 不启动 |
| 已输入密码，包括随后清空密码 | 本次卡片交互继续由用户手动接管 | 保持原行为 |
| 切换到其他账户或密码等登录方式 | 不抢回人脸登录，不猜测用户 | 保持原行为 |
| Windows 拒绝了已保存凭据 | 恢复事件不解除停止标记，提示使用密码 | 保留密码入口 |
| 已向 Windows 提交凭据／登录已经完成 | 不再启动另一轮 | 不再启动 |

合盖默认视为暂停本项目的相机识别；外接显示器、外接摄像头的闭盖使用场景
不在本轮自动策略中另设例外，仍可使用其他登录方式。没有盖子设备的台式机
不受这个条件限制。显示器由亮变暗不算熄屏，不触发新的识别周期。

本功能不更改 Windows 的“唤醒时要求登录”或合盖电源动作，不强制锁屏。
初版仅处理本地控制台登录／解锁；主机开盖不触发其他远程会话的识别。

## 当前问题与保留的规则

`credential.rs::SetSelected` 是现有主要启动入口。
`auto_runtime.rs::select_owned` 对相同 owner 的 `Stopped`／`Submitted` 不再启动，
用于防止 `CredentialsChanged` 重枚举产生无限重试或重复提交。

该保护保留，新增一个明确的恢复入口。不能简单删除“不重开”判断，也不能
只重新启动倒计时界面：认证 worker 本身必须接收事件、取消旧请求并重新计时。
若 Windows 已重建 LogonUI，原有首次选择路径可以启动识别，不能再额外启动一次。

## 职责与接入位置

| 位置 | 已实现的职责 |
| --- | --- |
| 新增 `power_events.rs` | 封装 Windows 通知、解析事件、管理回调注册与注销 |
| 新增 `wake_policy.rs` | 不调用 Windows API 的策略：事件归一化、周期去重、允许／抑制原因 |
| `provider.rs` | 在 Advise 完成 notifier 配置后建立订阅；UnAdvise／Drop 关闭订阅 |
| `credential.rs` | 将所选卡片、密码手动接管、提交中、凭据拒绝等状态同步给 runtime |
| `auto_runtime.rs` | 暂停与 `rearm_after_wake` 入口，取消 I/O、清除 grant、启动既有 worker |
| `auto_recognition.rs` | 继续负责单轮识别期限、重试次数、generation 与结果接受规则 |

电源订阅位于 Credential Provider 的后台组件内，不依赖 `Smile2UnlockStatus.exe`。
状态 EXE 继续只显示快照；它缺失、崩溃或无法覆盖时钟页，都不影响恢复后的识别。
第一版不新增常驻监督服务，也不修改服务的密码释放协议。

使用以下公开通知 API（Windows 8 起提供）：

- `PowerRegisterSuspendResumeNotification`，回调模式接收 suspend、automatic resume、
  interactive resume。
- `PowerSettingRegisterNotification`，回调模式接收 `GUID_LIDSWITCH_STATE_CHANGE`
  和 `GUID_SESSION_DISPLAY_STATUS`。CP 所在交互会话使用会话显示状态，不由服务
  的 session 0 接收该通知。
- `WTSGetActiveConsoleSessionId` 与 WTS 会话状态查询，在重新启动和接受结果前
  确认仍属于目标本地锁定会话。查询失败按不允许自动重启处理。

API 不可用或订阅失败时保留原有选择卡片／手动提交功能，记录失败原因。
缺少 lid 回调不代表盖子关闭；台式机和 VM 可依赖恢复及显示器通知。

## 状态与触发决策

策略维护以下概念，和单轮识别状态分开：

- 当前 provider 生命周期、选中 owner／SID／session，以及有效的自动识别设置。
- 电源暂停、盖子、显示器的已知状态；未知状态独立表示。
- `wake_cycle`、该周期是否已用于启动、是否有待处理的用户返回事件。
- 抑制原因：手动模式、密码接管、其他登录方式、Windows 凭据拒绝、提交中、
  登录完成、会话不可用。不能用一个 `password_entry` 布尔值概括所有原因。

密码的实际字符不进入策略模块。现有 `Cell`／`RefCell` 仍由 COM 线程访问，
只把必要的状态通过 runtime 锁同步给后台。

### 进入暂停状态

收到真实 suspend、已知开→合盖、已知显示器亮／暗→灭时：

1. 立即标记暂停并失效当前识别 generation，清除尚未提交的 grant。
2. 触发取消事件，中断 pipe I/O；既有断连机制通知服务停止相机代理。
3. 保留 owner 与用户手动接管／凭据错误标记，准备新的恢复周期。
4. 多个来源连续报告同一次离开，只记录同一个未消费周期。

若已处于 `Submitted`，记录暂停但不把状态回退为可重新提交。
已交给 Windows 的凭据等待 `ReportResult` 或 provider 生命周期结束。

### 用户返回

`PBT_APMRESUMEAUTOMATIC` 只表示系统恢复，不能单独启动识别。
交互恢复、真实闭→开、真实灭→亮可提供一次用户返回候选。
显示器明确关闭或盖子明确关闭时暂存候选，待限制解除；已解锁、换用户或
生命周期结束则丢弃候选。显示器未知时，交互恢复或已知闭→开可作为用户返回证据。

注册后的第一次 lid／display 值只建立基线，不能把“当前开着／亮着”解释成转换。
初始化阶段暂缓新的自动工作，先应用已知暂停条件；不会仅因 lid 设备没有回调
而无限等待。新建 provider 的正常首次选择与恢复候选统一经过同一个启动门槛。

启动前检查：本地控制台会话锁定、provider 仍有效、人脸卡片被选中、自动模式
开启、无上述抑制原因。设置变化后以重新读取的该用户配置为准。没有选中卡片
时不主动选中它；等正常选择回调再判断是否启动。

通过检查后，先消费 `wake_cycle`，再分配新的 request_id／generation，以恢复
后的单调时钟建立全新的总期限。等待用户配置的启动延迟，随后走既有识别 worker。
过去的 NoMatch／TimedOut 可以重开；凭据错误或用户手动接管不能被唤醒清掉。

### 去重与并发

去重以“离开—返回”的状态转换为主，不只比较两次通知的时间间隔。
同一轮的恢复、开盖、亮屏只允许一次启动；工作已排队或正在运行时不重新计时。
本轮超时后，重复报告“仍亮着／仍开着”也不增加预算，须新的离开—返回转换。

对没有先观察到 suspend 的交互恢复，建立一个恢复候选并合并其后附属事件；
若首次选择已经启动同一轮，则消费候选而不再启动。快速连续真实合盖／开盖
属于不同转换，旧请求必须完成取消后才能让新的请求占用相机。

事件回调不执行 COM 调用、相机调用或线程等待。暂停失效标记及取消事件必须
同步发布，不能仅排队等待 worker：worker 可能正阻塞在识别传输中。
worker 发布 grant 和 COM 消费 grant 时都重新检查当前 generation 与暂停状态，
因此暂停前的迟到结果不能穿过回调排队的时间窗口。

UnAdvise 先标记 runtime 关闭并取消工作，再交给后台清理订阅。回调令牌先撤销，
在途回调自行保留上下文；DLL 保持加载直到 LogonUI 进程结束。
不在 LogonUI COM 线程等待通知注销，也不让一次迟到回调影响下一次 Advise。

## 摄像头恢复、错误与提示

沿用已有启动延迟与单轮重试预算，不先增加一个任意的固定等待时间。
camera busy、设备暂时尚未恢复等暂时失败进入有限重试，不能无限延长本轮期限。
模型缺失、服务拒绝、存储凭据失效等继续停止，并保留密码登录入口。
实现时须核对 agent／service 的错误映射，不能把所有硬件错误都假设成可重试。

暂停时隐藏旧识别状态；真正开始新一轮后显示现有倒计时、扫描、重试和结果文案。
手动模式回到待命。时钟一级页面的可见性问题不作为本功能的前置条件，也不在
该设计中承诺已解决。

诊断仅记录事件来源、周期、generation、是否重开及抑制原因，不记录密码、grant
内容或人脸图像。这样后续可区分“没收到事件”“条件不允许”“相机没恢复”。

## 实现与本地验证

- `wake_policy.rs` 实现离开／返回转换与周期消费；初始样本和重复通知不补充重试预算。
- `power_events.rs` 在后台线程注册三类通知。注册期间暂缓首次识别，显示状态的
  首次回调最多等待 250 ms；这个等待只用于建立基线，不是恢复相机的固定延时。
  盖子没有传感器或没有回调时不会无限等待。注册失败记录错误并保留原登录入口。
- 回调上下文通过进程内、永不复用的令牌定位。注销前移除令牌，在途回调持有
  `Arc`，旧 provider 回调另受 epoch 校验；不依赖注销 API 隐含的等待保证。
  DLL 固定到 LogonUI 进程结束，沿用原有保守卸载策略。仅注销失败时保留注册参数内存，
  此时其令牌已撤销，不再保有运行时。COM 线程不等待注册／注销或相机。
- 暂停同步废弃 generation、清空未提交 grant，并置位取消事件。恢复后在同一 worker
  内等待旧传输结束，重新读取用户设置与 WTS 锁定状态，再开启新期限与 request ID。
- 密码实际编辑后设置持久接管状态，清空密码也不解除；凭据对象的拒绝／提交状态
  同步给 runtime。重复 `SetSelected` 仍保留原有停止保护。
- WTS 查询在状态锁外进行，提交策略前再次比较 owner、epoch、generation 与周期。
  恢复后的 grant 发布和消费前再次检查会话；查询失败不自动重开。
- 摄像头暂时失败继续使用现有 agent/service 错误映射和有限重试；不把服务不可用、
  模型错误或凭据错误改为无限重试。提示仍走已有状态快照，暂停时隐藏旧状态。

确定性测试覆盖旧 grant 失效、去重、初始通知、后台唤醒、手动模式、清空密码、
凭据拒绝、Submitted、设置变化、切换用户、迟到回调和旧 provider 的生命周期隔离。
还用阻塞的假传输和真实 Win32 取消事件证明：暂停后旧传输即便返回成功，也不能
发布密码；恢复只能使用下一次识别的新结果。

本地验证使用 Linux 主机交叉编译及独立 Wine prefix，不连接测试 VM，不注册真实
电源通知。密码保护往返的原有测试因 Wine 缺少 `CredIsProtectedW` 保持跳过。
这些检查不能证明实际设备会交付通知、26H2 一级时钟页会选中人脸卡片，或某型号
摄像头能够及时恢复；这些仍属于下面的后续实机验收。
