# 功能与设置

本文说明桌面应用中可配置的功能。控件可能按平台显示；Linux 不提供 Windows 锁屏识别触发策略。

## 账户与人脸

- 人脸页面通过摄像头采集并管理当前账户的人脸样本。档案由认证服务写入受保护存储。
- Windows 先保存当前账户密码，认证服务在 LocalSystem 边界内保管加密凭据；同一账户的多个人脸共用该凭据。
- Linux 人脸识别由 `su_authd` 执行，GUI 通过控制 socket 请求预览、录入和桌面认证检查。
- 失败识别抓拍默认关闭。开启后，抓拍内容会加密保存；设置可控制保留天数和数量，也可以查看或删除记录。

## 设置页

| 设置 | 作用 | 范围 |
| --- | --- | --- |
| 语言 | 选择简体中文或 English | Windows、Linux |
| 配色模式 | 跟随系统、浅色或深色；支持系统/DMS 提供的主题色 | Windows、Linux |
| 窗口按键 | 自动、显示或隐藏原生窗口控制 | Windows、Linux |
| 摄像头 | 选择用于录入和本地检查的摄像头 | Windows、Linux |
| 识别阈值 | 调整人脸匹配阈值，范围 0.25–0.95（默认 0.40） | Windows、Linux |
| 活体检测 | 开启或关闭防伪检查 | Windows、Linux |
| 活体阈值 | 设置活体分数阈值，范围 0.20–0.95（默认 0.76）；关闭活体检测时不可调 | Windows、Linux |
| 逆光补偿 | 根据画面亮度自动调整摄像头曝光 | Windows、Linux |
| 预览帧率 | 控制桌面预览的更新速度 | Windows、Linux |
| 自动识别 | 在 Windows 登录界面自动触发人脸识别 | Windows |
| 自动识别延迟 | 锁屏后开始自动尝试前的等待时间，0–60 秒 | Windows |
| 重试间隔 | 自动识别失败后的间隔，1–60 秒 | Windows |
| 识别超时 | 一次自动识别等待结果的上限，5–600 秒 | Windows |

修改后点击“保存设置”使策略持久化。界面会提示未保存的更改和保存结果。
自动识别策略在机器级保存；密码 tile 仍可用于手动登录。休眠期间自动识别计时暂停。

## 部署与诊断

- Linux 部署页通过 D-Bus/Polkit helper 管理认证服务、PAM 登录/锁屏目标和桌面集成；每项操作会显示目标状态与结果。
- Windows 部署页管理 Credential Provider 和认证服务。提权操作由独立 helper 完成，安全组件安装到受保护目录。
- 诊断页汇总服务、模型、摄像头和档案准备状态，并提供可执行的检查入口。
- 关于页展示当前构建版本、贡献者和离线许可证文本。

## 数据与隐私

人脸采集、特征提取和匹配均在本机完成。应用不会把生物特征上传到云端。
人脸档案使用加密封套存储；Linux 认证服务使用 systemd 管理主密钥，Windows
服务使用平台密钥保护机制。失败识别抓拍是单独的可选功能，默认关闭。
