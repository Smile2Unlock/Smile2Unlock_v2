# 失败识别抓拍

本功能默认关闭，在「设置 → 失败识别抓拍」中由每个账户自行开启。开启前会显示隐私说明；切换开关、调整保留天数和照片上限后，点击「保存设置」生效。设置卡片同时提供照片列表、缩略图、本地时区时间（格式为 `YYYY-MM-DD HH:MM:SS`）、失败原因、放大查看、单张删除和全部删除，不需要跳转诊断页面或导出诊断包。照片元数据仍以 UTC Unix 时间加密保存。

## 拍摄条件

只有系统解锁认证已经检测到人脸，且最终人脸不匹配，或检测到的人脸未通过活体检测时，才会尝试保存该次认证中质量较好的画面。没有检测到人脸、成功认证、取消、摄像头或模型不可用时不保存。应用中的人脸测试和预览不会生成解锁抓拍。

照片只在本机处理，不上传。画面保持宽高比，长边不超过 320 像素，使用约 70 的 JPEG 质量，单张 JPEG 不超过 45 KiB；超限或编码失败会放弃保存。缩略图和大图均来自服务返回的内存数据，不写明文临时图片。

## 存放位置和权限

- Windows：`%ProgramData%\Smile2Unlock\Users\<SID>\captures\`，沿用系统保护目录 ACL、现有主密钥及密钥保护机制。
- Linux：`/var/lib/smile2unlock/users/<uid>/captures/`，由 `su_authd` 使用现有系统凭据主密钥，目录权限 0700，文件权限 0600。

每张照片的元数据（随机 id、UTC Unix 时间、原因、宽高、JPEG 字节数）和 JPEG 一起加密到 `<id>.s2u`。复用人脸档案的 XChaCha20-Poly1305 加密封装和 HKDF 派生机制，使用独立的 Capture 数据种类；账户身份和数据种类参与密钥派生及认证，不能把另一账户或人脸档案文件当成照片解密。`retention.json` 只保存保留策略，不含照片元数据或图片。

查看和删除通过服务进行：Windows 校验管道调用者 SID 与目标 SID 完全相同；Linux 校验控制套接字 `SO_PEERCRED` UID 与目标 NSS 账户 UID 完全相同。照片管理不接受管理员跨账户访问；与档案新增/删除不同，查看、删除本人照片不额外索取管理授权令牌。持有系统主密钥的操作系统管理员仍处于本机信任边界内。

Windows 识别代理协议版本 2 使用明确请求标记；关闭时不编码或返回 JPEG。请求仍为 52 字节，响应固定 62,528 字节（含最多 45 KiB JPEG、特征及元数据），保留 magic/版本/nonce 校验。代理响应校验拒绝超限图片、未知标记、未请求的图片和无脸结果附带的图片。管理管道的固定消息布局不变，取图直接返回原始 JPEG，小于 48 KiB 响应载荷上限，无需分块。新增操作号 12–15；设置载荷从 32 字节扩展到 44 字节，旧设置文件缺省仍为关闭、7 天、50 张。

Linux 在已有识别流程中保留一帧有脸画面，最终拒绝时交给有界的后处理；`captures` 控制消息仅允许 list、fetch、delete、delete_all、configure，不允许客户端提交图片。取图使用有界 JSON 字节数组，最大 45 KiB 原始 JPEG，低于控制套接字 1 MiB 帧上限。

## 保留与删除

默认保留 7 天，最多 50 张。可设置 1–90 天、1–200 张，另有 20 MiB 照片总字节硬上限。达到期限或数量/字节上限后，按时间从旧到新删除，时间相同时按 id 排序。服务每分钟自动清理，也在写入、查看及调整策略时清理；自动清理仅在服务运行时进行，服务启动后恢复清理。

关闭抓拍后不再保存新照片；已经开始的认证也不能覆盖后来保存的关闭设置。已有照片仍按策略清理，也可以立即使用「删除全部照片」。删除照片不会自动关闭开关。删除人脸档案或使用 Windows 现有清除数据操作时，会一并删除该账户照片；删除失败会向调用者报告。

抓拍是尽力而为：认证结果先发送，再进行加密写入和保留处理；保存失败不会改变已经作出的认证决定。Linux 抓拍通过同一凭据提供器加载独立的密钥句柄，仍使用原有的锁页、空闲封存和禁止转储机制；抓拍文件 I/O 不持有认证主句柄的访问锁，避免慢磁盘阻塞后续认证。Windows 代理的编码工作有图像尺寸和字节上限，不延长现有代理总等待截止时间。日志仅记录 `capture.stored` 事件及 id、时间、原因，失败时只记录无敏感内容的失败事件；不记录图片、嵌入向量、nonce 或用户名。诊断导出不会收集抓拍目录。

## 开发验证

纯策略、格式、加密隔离、篡改、保留和关闭竞态测试位于 Rust core 的 `capture_policy.rs` / `capture.rs`，JPEG 边界测试位于 `tests/capture/image.cpp`。`tests/capture/control_socket.py` 在独立 user/mount namespace 中运行真实 `su_authd`，私有挂载 `/var/lib`，不修改宿主机数据、PAM 或服务。UI 渲染夹具在 `tests/capture/viewer.*`，支持 en / zh-CN 语言包及空列表、已有照片状态。

真实 Windows 安全桌面、摄像头、TPM/DPAPI、Linux 摄像头/真实锁屏仍需要各自系统上的设备验收；交叉编译和 Wine 不能替代该验收。
