# Windows 登录界面人脸识别提示

实现和 Windows 10 KVM 验证日期：2026-10-02。

## 外观与位置

提示位于当前 LogonUI 所在屏幕顶部居中，顶部距离屏幕高度约 8%，在用户头像上方。
窗口名义尺寸为 440 × 132 DIP，随 DPI 缩放，并限制在屏幕上部约 23% 范围内。
它只绘制图标、主提示和辅助文字，没有卡片底色、边框或摄像头画面。
文字与图标统一采用深色或白色，依据提示区域背景的线性亮度自动选择；细小的
反色描边用于提升复杂壁纸上的可读性。亮度采样排除自身已绘制的像素，并使用
滞回区间及两次一致采样避免反复闪烁。采样失效时隐藏，避免沿用另一桌面的背景。

Windows 10 19044 实机存在
`Windows\SystemResources\Windows.UI.BioFeedback\Fonts\NUIMDL2.ttf`。
显示进程通过 GDI+ 私有字体集合读取系统文件，用其中的扫描帧及成功图标绘制
Hello 风格动画；帧时序由本项目控制。没有调用未公开的 `FontGlyphAnimator`
WinRT 接口，没有将 Windows 字体或 DLL 分发到安装包。系统字体不可加载时退回
`Segoe MDL2 Assets` 的静态图标。系统私有字体的跨版本兼容性仍需实机验证。

提示采用 150 ms 淡入，不截取鼠标，不获取焦点，不增加登录按钮。
只有输入桌面为 Winlogon、前台窗口属于当前父 LogonUI 时才显示。某些 Windows
版本在时钟幕布上仍保持 LogonUI 为前台，且自动识别已启动，此时也显示其状态。
界面语言目前按系统 UI 语言选择中文或英文。

## 两种登录方式

| 实际状态 | 自动模式 | 手动模式 |
| --- | --- | --- |
| 已选择人脸登录 | 按已有设置显示开始倒计时 | 显示“按 Enter 开始人脸识别”，支持原登录箭头 |
| 捕获/识别中 | 扫描动画、“正在识别你…” | 同左，只在空密码提交后开始 |
| 暂时失败 | 在现有尝试预算内显示重试倒计时 | 一次失败后提示 Enter 重试或输入密码 |
| 整体超时 | 显示超时，使用密码或重新选择人脸登录 | 显示超时，可以手动重试 |
| 服务或配置不可用 | 显示不可用，提示使用密码 | 同左 |
| 识别通过 | 成功图标，随后自动提交 | 同左，不要求第二次 Enter |
| 正在提交 | “正在登录…” | 同左 |
| Windows 拒绝人脸凭据登录 | 停止自动尝试，提示检查保存的账户凭据 | 同左 |
| 输入密码 | 取消识别并隐藏提示 | 同左 |
| 清空已输入的密码 | 恢复手动待命，不擅自重启自动识别 | 恢复手动待命 |
| 切换用户/登录方式，或登录完成 | 隐藏并释放相应状态 | 同左 |

文案使用真实状态机及其截止时间；显示端不会推进认证或根据动画时长推断成功。
后端目前将多种暂时失败归并为同一个结果，因此显示“暂未通过验证”，不编造
“未检测到人脸”或“摄像头故障”等无法确定的原因。

## 进程与数据边界

- Rust credential provider 仅发布展示快照。它不在 COM/UI 线程创建窗口、绘图
  或等待显示进程；现有认证工作线程和凭据处理保持独立。
- `Smile2UnlockStatus.exe` 是独立的 Win32/GDI+ 进程，只在 LogonUI 中被启动。
  安装包必须包含并签名校验此文件；运行时缺失、退出或失败仅影响提示。
- 每个 provider 使用随机命名、仅 SYSTEM 可访问的本地共享内存。固定 24 字节：
  magic、协议版本、原子状态字、保留字段及单调时钟心跳。不传 SID、人脸图像、
  生物特征、密码或授权令牌。显示进程只读映射。
- 状态字低 4 位表示展示状态，bit 4 表示自动模式，bits 8–23 表示倒计时秒数。
  保留位或非法状态令显示端隐藏；协议见 `status.rs` 和 `status_host/protocol.h`。
- 发布每 100 ms 更新；心跳超过 1.5 秒不显示，超过 5 秒退出。父进程退出或
  provider 取消 Advise 时结束显示进程。旧卡片 owner 的回调不能覆盖新用户提示。
- 显示端不参与认证、授权、凭据准备或提交；它无法通过展示成功状态来完成登录。

## 构建与验证

`su_status_host` 作为 Windows 产品默认目标参与构建，生成
`Smile2UnlockStatus.exe`。打包、包验证及部署复制清单均包含此文件。
`su_windows_status_display_test` 覆盖跨语言状态字解码、保留位拒绝和亮度滞回，
并接入 Windows release-readiness 工作流。CP 套件覆盖倒计时、重试、超时、
Windows 返回结果，以及 owner 隔离、输入隐藏、成功隐藏和重新选择恢复等状态。

2026-10-02 测试环境为 Windows 10 IoT Enterprise LTSC 21H2 / build 19044、
2048 × 1280 的 KVM 虚拟机，使用已有 e2eSoft VCam 虚拟摄像头及已录入的档案。
本次在 `codex/windows-hello-status` 分支构建，包内版本沿用 2.3.1；这是本次
开发测试构建，没有修改发布 tag 或发布 GitHub Release。

已验证：

- 从主线重新生成的签名 NSIS 安装包安装返回 0；自动识别成功后无需 Enter，
  日志包含 `autologon=true`、一次 grant 消费及 `ReportResult status=0x0`。
- 首版带提示的签名安装包在真实 LogonUI 中完成自动人脸、手动人脸和密码登录。
- 暗色背景显示白字；临时独立白色测试窗口覆盖提示背后的区域后，提示变为黑色。
  白色区域仅用于对比度测试，不是产品卡片背景。
- 输入密码时提示隐藏，清空密码恢复待命，密码输入框及原提交按钮仍可用。
- 最终源码的 CP 套件在原生 Windows 上为 95 passed / 0 failed / 1 ignored；
  忽略项是已有的 CredProtect 兼容性测试。协议和亮度测试通过。
- 最终签名安装包安装返回 0；安装后的 CP DLL 和状态 EXE 的 SHA-256 与 ZIP
  内对应文件完全一致。最终包再次完成手动人脸和全程无按键的自动登录，登录后
  LogonUI 和显示进程均退出，没有遗留显示进程。
- 倒计时阶段强制结束显示进程后，认证继续进行并自动登录成功。
- 临时使用不存在的摄像头索引，日志记录三次失败重试，界面最终提示未通过验证；
  将初始延迟设为大于整体期限后，界面显示“人脸识别已超时”。两种情况下均能
  输入密码退出登录界面。

测试完成后，机器识别注册表恢复并逐文件哈希比对原备份，临时锁屏/截图任务与
安全桌面截图程序已清理，保留最终产品安装。旧注册表测试会写入并删除真实的
每用户识别缓存，本次将它隔离到专用测试子键；空缺的旧缓存由恢复后的服务配置
补齐，不再由测试改写真实偏好。

构建、安装、场景日志及截图保存在忽略目录
`build/windows-hello-status-20261002/`。测试使用用户原有虚拟摄像头，活体检测配置为
关闭，不能据此证明真人活体检测可靠性。Windows 11、多显示器、高 DPI、RDP、
系统冷启动和其他 Windows 私有字体版本仍需要单独验收。
